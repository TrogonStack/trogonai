# Trogon OCI media types

This reference lists every `application/vnd.trogon.*` media type, its `ArtifactType` variant, the layer-zero payload format, the referrer types it accepts and the repository layout. Implementers of `trogon-sandbox-oci`, the snapshot builder and workers should treat it as the wire contract.

The source of truth for the enum values is `ArtifactType::media_type()` in `rsworkspace/crates/sandbox/trogon-sandbox-contract`.

## Stability policy

| Version suffix | Guarantee |
|---|---|
| `v1` | Stable. A breaking change requires a new major media type (`v2`), not a silent edit. |
| `v2` and later | Additive fields preferred. A breaking layout change bumps the major version. |

No media type is deprecated today. When one is, its row moves into a deprecation section with the date and the replacement type.

## Primary snapshot artifacts

Leases restore from these types through `SandboxImage::Snapshot`.

### `application/vnd.trogon.sandbox.rootfs.v1+tar`

| Field | Value |
|---|---|
| `ArtifactType` | `SandboxRootfsV1` |
| Layer 0 format | A gzip-compressed tar archive of the container root filesystem |
| Typical providers | `LocalDocker`, `K8sMicroVm` |
| Optional `subject` | The base `OciImageRef` the rootfs was derived from |
| Allowed referrers | `SbomV1`, `ScanReportV1`, Cosign signature artifacts |

The Docker worker exports it from a committed container. The Kubernetes worker advertises it too and rolls leases back in place from it.

### `application/vnd.trogon.hyperlight.snapshot.v1`

| Field | Value |
|---|---|
| `ArtifactType` | `HyperlightSnapshotV1` |
| Layer 0 format | A single layer holding the serialized Hyperlight snapshot |
| Typical providers | `Hyperlight` |
| Optional `subject` | The module `OciArtifactRef` (`SandboxImage::HyperlightModule`) |
| Allowed referrers | `SbomV1`, `ScanReportV1`, Cosign signature artifacts |

### `application/vnd.trogon.firecracker.snapshot.v1`

| Field | Value |
|---|---|
| `ArtifactType` | `FirecrackerSnapshotV1` |
| Layers | One layer per snapshot file, with the layer media type `application/vnd.trogon.firecracker.<file>.v1`, suffixed `+gzip` when compressed |
| Typical providers | `Firecracker` |
| Manifest annotation | `io.trogon.sandbox.env-digest`, the execution environment digest |
| Allowed referrers | `SbomV1`, `ScanReportV1`, Cosign signature artifacts |

A Firecracker snapshot only resumes under the environment that produced it. See [Snapshot store](../../architecture/sandbox/snapshot-store.md) for how the environment digest is recorded and checked.

### `application/vnd.trogon.kubevirt.disk.v1+qcow2`

| Field | Value |
|---|---|
| `ArtifactType` | `KubevirtDiskV1` |
| Layer 0 format | A qcow2 disk image |
| Typical providers | `KubeVirt` |
| Allowed referrers | `SbomV1`, `ScanReportV1`, Cosign signature artifacts |

## Supply-chain referrer artifacts

These attach through the OCI `subject` field to a primary snapshot manifest. They are not valid restore inputs on their own.

### `application/vnd.trogon.sbom.v1`

| Field | Value |
|---|---|
| `ArtifactType` | `SbomV1` |
| Layer 0 format | CycloneDX JSON generated by Syft |
| `subject` | Required: the digest of the primary snapshot manifest |
| Allowed referrers | None |

### `application/vnd.trogon.scan-report.v1`

| Field | Value |
|---|---|
| `ArtifactType` | `ScanReportV1` |
| Layer 0 format | The Trivy JSON report |
| `subject` | Required: the digest of the primary snapshot manifest |
| Allowed referrers | None |

With `SANDBOX_REQUIRE_SCAN_PASS` on (the default), a snapshot that fails the scan is not published.

## Cosign signatures

Cosign signature manifests use the upstream media types and are not `ArtifactType` variants. They attach as referrers with `subject` set to the snapshot digest. Verification happens at pull time through Cosign, not through `ArtifactType` matching.

## Referrer matrix

| Primary type | May attach |
|---|---|
| `SandboxRootfsV1` | `SbomV1`, `ScanReportV1`, Cosign |
| `HyperlightSnapshotV1` | `SbomV1`, `ScanReportV1`, Cosign |
| `FirecrackerSnapshotV1` | `SbomV1`, `ScanReportV1`, Cosign |
| `KubevirtDiskV1` | `SbomV1`, `ScanReportV1`, Cosign |
| `SbomV1` | None |
| `ScanReportV1` | None |

Discover referrers with `oras discover`, or with `trogon-sandbox-oci`, which uses the Referrers API and falls back to the tag scheme. The fallback is counted in `trogon_sandbox_oci_referrers_fallback_total`.

## Repository layout

Primary snapshot repositories are named by tenant:

```text
snapshots/<tenant>
snapshots/tenant-hex/<hex of the tenant id>
```

The second form applies to tenant ids that contain `:` or `/`. See [KV key layout](../../architecture/sandbox/kv-key-layout.md) for why.

Runtime lookups use the `sha256:` digest recorded in the `sandbox-broker-kv-snapshot` bucket, never a mutable tag. Tags exist for operator navigation and retention only. Referrer artifacts attach to the primary manifest digest and do not occupy separate top-level repositories.

The bundled Zot registry chart sets the root prefix through `repositoryLayout.conventions.snapshotPrefix` (default `snapshots`) in `devops/helm/sandbox/charts/zot/values.yaml`. Tenant access is limited to pull on the tenant's own repository. See [Tenant-scoped snapshot registry RBAC](../../architecture/sandbox/registry-rbac.md).

## Providers without a registry snapshot

| Provider | Snapshot media type |
|---|---|
| `Subprocess` | Not applicable |
| `AzureContainerApps` | None. The worker advertises no snapshot support. |
| `Daytona` | None. The worker advertises no snapshot support. |
| `Modal`, `E2b` | Provider-native snapshots, not OCI artifacts. See [Snapshot store](../../architecture/sandbox/snapshot-store.md). |
